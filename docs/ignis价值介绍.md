# Ignis—让你随时随地访问自己的Obsidian

> Ignis 官方 https://github.com/Nystik-gh/ignis

---

## 一、一句话概括

**Ignis 让你用浏览器打开 Obsidian（笔记软件），笔记文件却保存在你自己的服务器上。** 它就像一个"翻译官"，把 Obsidian 内部依赖的 Electron（桌面应用框架）功能，翻译成浏览器能理解的语言，让原本只能跑在电脑上的 Obsidian，变成可以在任何设备上通过浏览器访问的 Web 应用。

打个比方：Obsidian 原本是个"只会说 Electron 语"的外国人，Ignis 是随行的翻译——它不改变外国人本人，只是让他在"浏览器"这个新的环境里也能正常生活。

---

## 二、解决的问题

### 2.1 痛点：Obsidian 的远程访问体验很差

Obsidian 是**本地优先**的笔记软件，这带来一个天然问题：**离开自己的电脑，就访问不了笔记**。

在 Ignis 出现之前，想在别的设备上访问自己的 Obsidian，主流方案是 **VNC（远程桌面）**——把你整台电脑的屏幕"直播"到另一台设备上操作。体验很差：

- 卡顿、掉帧、画面模糊
- 依赖完整的桌面会话，资源占用高
- 手机上操作小窗口里的桌面界面，极其别扭

### 2.2 Ignis 的解法：服务器上跑 Obsidian，浏览器当客户端

Ignis 的做法完全不同：

- Obsidian 本体跑在**你的服务器**上（文件也都在服务器上）
- 你通过任意设备的**现代浏览器**访问，界面和原生桌面几乎一样
- 不需要远程桌面、不需要虚拟机、不需要 VNC

这就把"本地优先"的 Obsidian 变成了"私有云笔记"——**笔记永远是自己的，访问却随处可得**。

## 三、核心优势

### 3.1 接近原生的使用体验

- **完整的核心功能**：编辑器、画布（Canvas）、白板（Bases）、命令面板、右键菜单、主题和 CSS 片段全部可用
- **不是远程桌面**：直接以 Web 应用形式渲染，流畅度和观感都远好于 VNC
- **小屏幕自适应**：在小屏幕上自动切换到移动端界面，手机平板也能用

### 3.2 生态兼容：大多数社区插件能用

Obsidian 之所以强大，很大程度上靠**海量社区插件**。Ignis 实现了浏览器版的插件运行环境，大多数基于 Obsidian 插件 API 开发的插件都能正常运行。

只有依赖"浏览器没有的能力"的插件无法工作，比如：
- 需要在系统里启动外部程序的（`child_process`）
- 需要打开原始网络套接字的（`net`）
- 需要加载编译过的原生模块的（`.node` 二进制）

### 3.3 数据自主可控

- 笔记文件（Vault）完整保存在你自己的服务器上，**不经过任何第三方**
- 支持创建、打开、切换、重命名、删除多个 Vault
- 每个浏览器标签页可以打开**不同的 Vault**

### 3.4 多端实时同步

- 多个浏览器标签页之间通过 WebSocket **实时同步**，编辑内容 1 秒内传播
- 保存的 workspace 布局可以用 `?workspace=` 参数在独立标签页打开
- 支持 Obsidian Sync（登录标签页内），也支持 **Headless Sync**——服务器端同步，**即使没有浏览器标签页开着也能同步**

### 3.5 插件请求代理（CORS 代理）

浏览器跨域请求有安全限制，很多插件（如下载主题、访问外部服务）会因此失败。Ignis 内置了**服务端代理**，帮插件完成跨域请求，并带完整的 SSRF 防护（默认禁止访问内网/私网地址）。

### 3.6 部署简单，一键启动

Docker 部署，一个 `docker-compose.yml` 文件即可启动：

```yaml
services:
  ignis:
    image: nobbe/ignis:latest
    ports:
      - "8080:8080"
    volumes:
      - ./vaults:/vaults
      - ./data:/app/data
      - obsidian-app:/app/obsidian-app
    restart: unless-stopped
```

Obsidian 本体由容器在**首次启动时从官方源自动下载**，项目本身不捆绑、不分发任何 Obsidian 代码（遵守版权）。

## 四、面向的用户群体

### 4.1 重度 Obsidian 用户，且有多端访问需求

- 上班用公司电脑、回家用自己电脑、路上用手机，希望**所有设备看到的都是同一份笔记**
- 不想用 VNC，想要接近原生的体验
- 能接受自托管（有一台服务器、VPS 或 NAS）

### 4.2 数据敏感、希望完全掌控数据的人

- 不想把笔记放在第三方云笔记服务的服务器上
- 愿意自己部署、自己保管数据

### 4.3 技术爱好者 / 自托管玩家

- 熟悉 Docker、反向代理（Caddy、nginx、Traefik）、VPN（Tailscale 等）
- 享受自己搭建、自己维护一套私有服务的过程

### 4.4 团队/私有知识库场景

- 用 Obsidian 做团队知识管理，需要团队成员通过浏览器访问共享笔记
- 搭配反向代理 + 认证（Authelia 等）实现受控访问

> **适合什么样的人**：有一定技术基础，愿意为"数据自主 + 随处可访问"付出部署和维护成本的人。
> **不适合的人**：只想开箱即用、不想碰服务器的人，建议直接用 Obsidian 官方付费同步或第三方云笔记。

## 五、这个项目的价值

### 5.1 给用户的直接价值

| 价值 | 说明 |
|---|---|
| **释放 Obsidian 的远程能力** | 把"本地优先"的软件变成"私有云"应用，弥补了 Obsidian 官方在远程访问上的空白 |
| **体验远优于 VNC** | 接近原生 Web 应用，而非"看远程桌面" |
| **数据主权** | 笔记永远在自己手里，服务器是自己的，数据是自己的 |
| **生态延续** | 不换工具、不迁移数据，继续用 Obsidian + 既有插件体系 |

### 5.2 技术上的独特之处

- **兼容层思路**：不修改 Obsidian 一行代码，通过实现浏览器版的 Electron API（shim 层）让 Obsidian 以为自己还在桌面环境——这个思路非常巧妙，保证了版本升级时的兼容策略（工程已适配 Obsidian 1.13.7 / Electron 39）
- **性能设计**：预压缩启动响应、内容缓存（50MB LRU）、写合并（慢速文件系统如 NFS/SMB 优化）、批量预取
- **安全设计**：路径双重防护（防目录穿越）、SSRF 四层防护、错误信息脱敏

### 5.3 项目定位与现状

- 项目状态：**积极开发中**（作者自己的每日笔记主力工具），当前版本 0.8.10
- 形态：目前是**自托管服务器**，桌面插件版本（在桌面 Obsidian 内运行 Ignis 服务器）在规划中
- 路线图方向：移动端改进与 PWA 支持、服务端插件安全模型、内置认证与访问控制

### 5.4 一句话价值总结

> **Ignis 填补了 Obsidian"本地优先"与"随处访问"之间的鸿沟**——用巧妙的兼容层技术，把一款优秀的桌面笔记软件，变成了数据完全自主的私有云笔记服务，同时保住了 Obsidian 的完整功能与插件生态。

## 附：名词速查

| 名词 | 含义 |
|---|---|
| **Vault（库）** | Obsidian 里的笔记集合，一个文件夹即一个 Vault |
| **Electron** | 桌面应用框架，Obsidian 桌面版基于它构建 |
| **Shim（兼容层）** | 一套"冒名顶替"的接口实现，让程序以为环境没变 |
| **VNC / 远程桌面** | 把整台电脑屏幕远程直播的方案，Ignis 要替代的旧方案 |
| **Headless Sync** | 服务器端后台同步，无需打开浏览器也能同步笔记 |
| **CORS 代理** | 帮助浏览器跨域请求的服务端中转 |
| **SSRF** | 服务器端请求伪造攻击，Ignis 有专门防护 |
